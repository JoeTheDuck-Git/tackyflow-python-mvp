# TackyFlow AI 串接地圖

更新日期：2026-09-25

## 原則

- 所有需要語意理解、研究、生成或編輯判斷的工作，先統一使用 OpenAI Responses API 與 `gpt-5.6-sol`。
- 所有權限、額度、狀態轉換、資料保存、刪除、發布核准與 Workspace 隔離維持確定性程式邏輯。
- AI 輸出使用 Structured Outputs；引用、Token、模型、提示詞版本和失敗狀態必須保存。
- 沒有引用不等於失敗，但資料信心不可標為高；外部模型失敗時不可靜默換成本機內容並假裝成功。
- Gemini Key 目前只保留，尚未啟用。未來僅在「直接讀取公開 YouTube URL」成為核心需求時評估作為影片擷取 adapter。

## 建議的實際呼叫順序

```text
內容機會研究代理（OpenAI + Web Search）
  ↓
內容機會策略代理（OpenAI Structured Outputs）
  ↓
研究代理（OpenAI + Web Search）
  ↓
驗證代理（僅高風險／低引用／關鍵數字時呼叫）
  ↓
撰寫代理（OpenAI Structured Outputs）
  ↓
本機字數、結構與禁用詞檢查
  ↓
品質主編（OpenAI Structured Outputs，回寫修訂稿）
  ↓
製作規劃代理（OpenAI Structured Outputs）
  ↓
完整預覽與人工核准（不呼叫 AI）
```

內容機會已拆成研究與策略兩段，避免 Web Search 與大型結構化輸出綁在同一個長請求。工作台一般任務會呼叫研究、撰寫、品質主編與製作規劃共 4 次；只有高風險、低引用或研究信心不足時才增加第 5 次驗證呼叫。
生成額度以「使用者建立的一個內容任務」計算一次；各代理的 Token、response ID 與完成／失敗事件仍分開保存。

## 下一階段驗收條件

1. OpenAI 模式的執行紀錄不得出現 `is_simulated=true` 的代理完成項目。
2. 研究代理每個可驗證主張需包含來源 URL 與觀察日期。
3. 驗證代理只處理研究代理標記的主張，不重做整份研究。
4. 撰寫代理必須引用研究 artifact，而不是重新憑模型記憶撰寫。
5. 品質主編需保存修改前後差異，不可只回傳分數。
6. 製作規劃的每個分鏡必須對應腳本 section ID。
7. 每次模型呼叫保存 provider、model、response ID、Token、耗時、prompt version 與失敗類型。
8. 任何外部呼叫失敗都要顯示可重試狀態，不可默默改用本機模板。
